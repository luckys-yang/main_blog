STM32 32位处理器分类详细信息参考：https://www.st.com.cn/zh/microcontrollers-microprocessors/stm32-32-bit-arm-cortex-mcus.html

字节对齐

结构体的首地址不是4的整数倍时，直接用uint32_t强制转换会出现硬件错误导致死机。问题原因是内存访问机制，要求uint32_t 指向的地址最低2bit必须是 0，uint16_t 指向的地址最低1bit必须是0。也就是说32位数存放在RAM里的地址必须是4的倍数，16位数存放在RAM里的地址必须是2的倍数

外部SRAM需要注意

浮点单元FPU

浮点计算的2种实现方法：

  1. 【软浮点】通过浮点库去实现浮点运算的，效率低，成本低，编译环境支持浮点库，可以将用C语言写的浮点数运算转成整形运算，对于单片机来说根本不知道float、double这回事，所以单片机不需要有专门的浮点运算单元就可以算浮点数了
  2. 【硬浮点】通过浮点运算单元（FPU）来完成的，效率高，成本高，F4支持FPU，但是不是一定要用，需要配置
  • 编程时不需要考虑CPU的软浮点或者硬浮点特性，直接用C编程实现功能，然后设置好后直接编译，按照这样的规则编译：浮点运算可以用硬浮点时用FPU，如果不能用硬浮点就自动用软浮点来实现
  • F4内部FPU只能算float不能算double
  • F4内部FPU只能算float的简单加减乘除，不能算float的sin、cos等复杂运算

keil里对于有FPU功能的芯片默认打开了

芯片内部Flash与SRAM

参考文章：

  • https://www.cnblogs.com/xiaobaibai2021/p/15716900.html

**FLASH(闪存)**用来存储程序的，掉电后数据不丢失的存储器(FLASH芯片只能一大片一大片地擦除，而EEPROM可以单个字节擦除)

**SRAM(静态随机存取存储器)**是用来存储运行程序中的中间变量(STM32F1系列可以通过FSMC外设来拓展SRAM)

注意：SRAM和SDRAM是不相同的，SDRAM是同步动态随机存储器，同步是指内存工作需要同步时钟，内部的命令的发送与数据的传输都以它为基准；动态是指存储阵列需要不断的刷新来保证数据不丢失；随机是指数据不是线性依次存储，而是自由指定地址进行数据读写

在keil的 .map 里面可以看到程序的这些用量

Code：代码空间，本质是ARM指令（ FLASH）

RO-data：即 Read Only-data， 表示程序定义的常量，如 const 类型（ FLASH）

RW-data：即 Read Write-data， 非0初始化的全局和静态变量占用的RAM大小，同时还要占用等量的ROM大小用于存放这些非0变量的初值（FLASH+RAM）

ZI-data：即 Zero Init-data， 0初始化的内存区的大小（该区域3个用途：0初始化的全局和静态变量+堆区+栈区）(RAM)

由上可知：

程序占用 FLASH=Code + RO-data + RW-data 即map文件中ROM size

程序占用 RAM = RW-data + ZI-data 即map文件中RW size

注意：

  • RAM掉电数据会丢失，RW-data是非0初始化的数据，已初始化的数据需要被存储在掉电不会丢失的FLASH中，上电后会从FLASH搬移到RAM中
  • 因为ZI数据是0，没必要包含，只要在程序运行前把ZI数据区域一律清零即可，包含进去反而浪费Flash存储空间，所以烧录的 bin/hex 文件不包含这个

如果是用makefile编译的话会生成下面这样子的数据(单位字节)：

text（代码段）： 存放程序的可执行指令代码。编译器将源代码编译生成的机器指令存储在这个段中

data（数据段）： 存放程序中已经初始化的全局变量和静态变量。这些变量在程序编译时就已经确定了初始值

bss（Block Started by Symbol）： 存放未初始化的全局变量和静态变量。这些变量在程序加载时会被系统自动清零

dec（十进制数）： 是 text、data、bss 三个段的总和，表示程序在内存中占用的总空间大小

text 段通常存储在 ROM（如 Flash）中，因为代码是只读的

data 和 bss 段通常存储在 RAM 中，因为程序运行时需要对数据进行读写操作

也就是上面这样意思就是程序已经占用：

16KB Flash + 2.6KB RAM

  • stm32的复位地址是从 0x0000 0000 开始
  • flash地址起始于 0x0800 0000，结束地址是 0x0800 0000加上芯片实际的flash大小
  • RAM起始地址是 0x2000 0000，结束地址是 0x2000 0000加上芯片的RAM大小

上面图中

  • Flash: 0x08000000 ~ 0x00010000
  • RAM: 0x20000000 ~ 0x00005000

可以通过Size算出芯片的flash跟ram分别是多少？

0x5000 -> 20k

0x10000 -> 64k

其他：

stm32芯片烧写时，就是将软件编译生成的目标代码，烧写到0x08000000地址起始的flash中，如果目标代码小于芯片flash的容量，则最后一段flash就是空闲的。这一段空闲区域就可以用来存储用户的数据，实现掉电不丢失

关于 GCC 编译生成的 bin 文件太大的问题

发现同一个工程配置用keil编译出来的比用gcc编译出来的小很多 差不多10k

解决方法：

  • 避免使用 printf() 等 C 语言标准库函数可以大幅减小 bin 文件的体积
  • 在 Makefile 中不使用 -u _printf_float 和 -u _scanf_float 参数可以大幅减小 bin 文件的体积，只是这样 C 标准库中浮点数和字符串互转的功能就不起作用了
  • 删掉没有使用的函数也能缩小 bin 文件大小
  • GCC 编译出来的文件虽然大，但它和 Keil 编译出的文件关系也只是加法不是乘法
  • 如果使用了 OS 的话，那几乎可以肯定它是一定使用了 C 标准库的函数了
